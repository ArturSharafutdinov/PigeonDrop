# Сервис распознавания речи (`stt/`)

Маленький HTTP-сервис: на вход WAV, на выход текст. Внутри Parakeet TDT 0.6B v3 (int8) на процессоре, через `onnx-asr`. Он работает в отдельном контейнере рядом с сервером PigeonDrop, а очередь, повторы и хранение текста ведёт сам сервер (проект: [`STT_SERVICE_PLAN.md`](../STT_SERVICE_PLAN.md), выбор модели: [`STT_COMPARISON.md`](../STT_COMPARISON.md)). Сервис ничего не знает про пользователей, записи и базу, поэтому модель меняют заменой образа.

Только стандартная библиотека Python для HTTP; тяжёлые библиотеки (`onnx-asr`, `numpy`) подгружаются лишь вместе с моделью, поэтому сервер и его тесты запускаются без них.

## Протокол

| Запрос | Ответ |
|---|---|
| `POST /v1/transcribe`<br>`Content-Type: audio/wav` (WAV 16 кГц, 16 бит, моно)<br>`Authorization: Bearer $STT_TOKEN`<br>`X-Request-Id: ...` (необязательно) | `200` `{"text", "language", "engine", "audio_ms", "stt_ms"}` |
| (звук не такой или не WAV) | `400` `{"code": "bad_audio", "message"}` |
| (длиннее `MAX_AUDIO_SECONDS` или тело больше допустимого) | `413` `{"code": "too_long"}` |
| (нет или неверный токен) | `401` `{"code": "unauthorized"}` |
| (другой `Content-Type`; нет `Content-Length`) | `415` / `411` |
| (в этот момент распознаётся другая запись) | `429` `{"code": "busy"}` и `Retry-After: 5` |
| (модель ещё загружается) | `503` `{"code": "loading"}` и `Retry-After: 10` |
| (сбой модели на этой записи) | `500` `{"code": "internal"}`; подробности только в журнале |
| `GET /healthz` | `200` `{"ok": true, "engine"}`, пока модель не загружена `503` |

- Каждый ответ JSON в UTF-8 и несёт `X-Request-Id` (присланный, если он из букв, цифр и `._-` до 64 знаков, иначе созданный).
- `text` пустой, если речи нет: это успех, а не ошибка. `language` равен `null`: Parakeet сам язык не сообщает.
- **Одна запись за раз.** Вторая, пришедшая во время распознавания, получает 429 и не ждёт; очередь ведёт вызывающая сторона. Проверка здоровья отвечает и во время распознавания.
- Тело читается целиком и до всякого отказа, если его длина допустима: сервер, который отвечает и закрывает соединение, пока клиент ещё шлёт, показывает клиенту сброс соединения вместо ответа. Длина ограничена (`MAX_AUDIO_SECONDS` × 32 000 байт + 4 КиБ), таймаут соединения 30 секунд.
- В журнал (одна строка JSON на запрос, в stderr) не попадают ни звук, ни текст, ни токен: только идентификатор запроса, код, длительности и число знаков.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что |
|---|---|---|
| `STT_TOKEN` | **обязательна** | общий секрет с сервером; без него сервис не запускается |
| `STT_INSECURE` | нет | `true` разрешает пустой токен. Только для опытов вручную |
| `PORT`, `HOST` | `8000`, `0.0.0.0` | где слушать |
| `MAX_AUDIO_SECONDS` | `65` | самая длинная запись. Память проверена до 60 секунд: выше не поднимать без нового замера |
| `STT_THREADS` | сам | число потоков модели; по умолчанию столько, сколько контейнеру реально можно (меньшее из ядер и квоты `--cpus`), потому что лишние потоки при квоте не ускоряют, а замедляют |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warning`, `error` |

Все неверные значения сообщаются сразу вместе, процесс при этом завершается кодом 2. Если модель не загрузилась, процесс завершается кодом 1 (Docker перезапустит контейнер).

## Запуск и ресурсы

```bash
docker build -f stt/Dockerfile -t pigeondrop-stt stt      # из корня репозитория; скачивает модель, около 1,6 ГБ
docker run --rm -p 127.0.0.1:8000:8000 -e STT_TOKEN=опыты \
  --memory=3g --memory-swap=3g --cpus=2 pigeondrop-stt
```

- **Память 3 ГБ без подкачки.** Потолок при записях до 60 секунд составил 2,23 ГБ, при 2 ГБ контейнер убивается (`STT_COMPARISON.md`, раздел 7.4).
- **Порт наружу не публиковать.** Сервис для внутренней сети сервера; токен только вторая линия защиты.
- Контейнер не пишет на диск (звук разбирается в памяти, временных файлов нет), поэтому годится корневая файловая система только для чтения.

## Авторство и лицензия модели

Сервис запускает NVIDIA Parakeet TDT 0.6B v3 (`nvidia/parakeet-tdt-0.6b-v3`), лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/): указывать авторство обязательно. Веса берутся в виде, в каком их опубликовал istupakov для библиотеки [`onnx-asr`](https://github.com/istupakov/onnx-asr) (конвертация в ONNX, `istupakov/parakeet-tdt-0.6b-v3-onnx`, вариант int8, лицензия та же); мы модель не меняли. Образ содержит веса внутри, поэтому всякий, кому он передан, получает и эту лицензию. Где авторство показывается людям: страница `/pair` (`backend/internal/httpapi/pair.html`), `backend/README.md`.

## Проверка

```bash
cd stt && python3 -m unittest discover -s tests -t .      # без Docker и без модели, секунды
./smoke.sh ../bench/stt/data/wav                          # настоящий образ с лимитами, ваши записи; нужен собранный образ
```

Тесты поднимают настоящий сервер на свободном порту с подменной моделью: токен и его отсутствие, все виды плохого звука, лимиты длины и тела, «занято» при втором запросе, сбой модели без остановки сервиса, журнал без текста и токена. Каждая из защит проверена поломкой: тесты падают, если её убрать.

`smoke.sh` запускает образ с лимитами из раздела выше, отправляет каждый WAV из каталога несколько раз и сверяет текст с результатами стенда (`bench/stt/results`, если они есть), затем печатает память контейнера. Это единственное место, где настоящая модель получает звук из памяти: тест подменной моделью этого не доказывает.

Результат при выпуске (2026-10-10, Mac с Apple M4 Pro, образ 1,58 ГБ, сборка около 3 минут, лимиты `--memory=3g --cpus=2`): 21 запись по 2 круга, 42 запроса, **ни одной ошибки; все 21 текст совпали с результатами стенда** (то есть звук из памяти через сервис даёт тот же текст, что чтение файла), 353 секунды звука распознаны за 18 секунд, память контейнера в конце 1,98 ГиБ из 3, убийств по памяти нет, от непривилегированного пользователя модель читается из образа без записи на диск.

## Что не проверено

- Скорость и память на VPS: все цифры с Mac на Apple M4 Pro, ядро которого быстрее типичного ядра VPS.
- Образ собирается и запускается проверенно только на arm64 (Mac); сборка для x86 (VPS) делается в CI на этапе развёртывания, и там `smoke.sh` нужно повторить.
- Долгая работа одного процесса: память проверена стендом (`STT_COMPARISON.md`, 7.4) на движке `onnx-asr` напрямую, а не через этот сервис.
- Две записи одновременно не поддерживаются намеренно (429); нужна ли параллельность, покажет замер на VPS.
