## 1. Условия и критерии

Ответы владельца от 2026-10-05:

- **Аудитория:** ЕС и весь мир (значит, важны GDPR и место обработки данных).
- **Языки:** сейчас русский; при публикации английский и другие языки. Модель должна **меняться без боли**.
- **Объём на первом этапе:** до 1 000 минут в месяц на весь сервис.
- **Облако допустимо, но лучше локальная модель.** Ресурсы VPS ограничены; можно докупить 4 ГБ RAM.

Что подаём на вход: запись до 60 с, на сервере лежит оригинал Ogg/Opus (SILK, 16 кГц, моно), а WAV 16 кГц делается из него при необходимости (`backend/internal/httpapi/recordings.go`, `decodeToWAV`). Минута звука в WAV занимает около 1,9 МБ.

Критерии: качество на русском и на звуке с часов (микрофон на запястье, шум, ветер); языки; цена; где обрабатываются данные; нагрузка на VPS; насколько легко заменить решение.

Значит, нагрузка на процессор терпима, если распознавать по одной записи в фоне. Узкое место — память: модели занимают 1,2–2 ГБ, а контейнер сервера на VPS ограничен 512 МБ (`backend/DEPLOY.md`), поэтому распознаватель должен быть отдельным контейнером.

## 5. Как сделать замену модели лёгкой

Идея: расшифровку делает интерфейс, а не конкретный сервис. Эскиз для Go (не реализовано):

```go
type Transcriber interface {
    Transcribe(ctx context.Context, wav io.Reader, opts Options) (Result, error)
}

type Options struct {
    Language string   // "" означает автоопределение
    Hints    []string // слова, которые стоит угадывать
}

type Result struct {
    Text     string
    Language string  // что определила модель
    Provider string
    Model    string
    Seconds  float64 // длительность звука, из неё считается стоимость
}
```

Как это даёт заменяемость:

- **Два вида адаптеров закрывают почти всё.** Первый — «OpenAI-совместимый» `POST /v1/audio/transcriptions`: так отвечают OpenAI, Groq, DeepInfra и локальные серверы (whisper.cpp, обёртки над Parakeet от сообщества), различаются только адрес, ключ и имя модели. Второй — родные адаптеры (Deepgram, AssemblyAI, Mistral, Google и др.), добавляются по мере надобности.
- **Всегда слать WAV 16 кГц.** Его понимают все; сервер уже умеет делать его из оригинала. Ogg/Opus принимают не все (у OpenAI он не перечислен).
- **Выбор по языку и настройке.** Таблица «язык → поставщик» в конфигурации: например, русский и английский на локальную Parakeet, остальное на облако. Смена поставщика — правка конфигурации.
- **В каждой расшифровке хранить:** поставщика, модель, язык, длительность и стоимость. Тогда при смене модели старые тексты остаются объяснимыми, а расходы считаются.
- **Распознавание — фоновая задача**, а не часть загрузки записи: загрузка с часов не должна ждать модель (см. очередь в `STACK_COMPARISON.md`, тема 4).

## 6. Мой выбор

Это моё мнение; решать по таблицам и по замеру (раздел 7) вам.

1. **Сейчас, пока нет локального распознавателя:** облако через адаптер «OpenAI-совместимый» плюс выбор по языку. По умолчанию **Mistral Voxtral Mini Transcribe V2** ($3 за 1 000 минут, данные в ЕС, русский входит), для языков вне его списка — **OpenAI gpt-transcribe**. Для бесплатного старта подходит Cloudflare Workers AI, но политика хранения данных у него не проверена.
2. **Следом, как вы хотите — локально:** отдельный контейнер с **Parakeet TDT v3 (int8)**: лимит 2–3 ГБ, одна запись за раз, пониженный приоритет процессора. Он покрывает русский, английский и ещё 23 европейских языка без платы за минуту. Для остальных языков остаётся облако.
3. **GigaAM v3** — запасной вариант «русский специалист», если на ваших записях Parakeet окажется хуже. **Whisper turbo** — запасной локальный вариант для языков вне Европы.
4. **Не решать по чужим цифрам:** все WER выше получены на других записях, у других голосов, с обычными микрофонами. Ваш звук (запястье, шум, SILK 16 кГц) непохож на них.

## 7. Замер на ваших записях

**Статус: запланирован, не выполнен.** Порядок утверждён владельцем 2026-10-05:

2. **Облачные решения** по тому же принципу и на тех же записях (ключи вы кладёте в переменные окружения сами).
3. **Выбор** делает владелец; результаты замеров будут добавлены в этот раздел таблицей: ошибки слов и знаков (WER, CER), процессорные секунды на минуту звука, пиковая память, время загрузки модели, определение языка, пунктуация, выдуманный текст на паузе.

Результаты на ~20 записях одного голоса показывают порядок и слабые места, а не точный WER.

## 8. Что осталось непроверенным

- Точность любого решения на звуке с часов: все цифры WER выше получены другими людьми на других записях.
- Скорость и память локальных моделей на вашем VPS (все цифры — со сторонних машин).
