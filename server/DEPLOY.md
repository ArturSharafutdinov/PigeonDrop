# Деплой на Railway

Заменяет запуск через ngrok на постоянный публичный адрес. Инструкция ручная — создание аккаунта, привязка карты и сам деплой это ваши собственные действия, здесь просто последовательность шагов.

## Почему Railway

Сервер хранит состояние в локальных JSON-файлах (`data/accounts.json`, `data/uploads.json`) и папке `uploads/` — не в базе данных. Значит нужен **персистентный диск**, который переживает рестарт/редеплой, а не эфемерная файловая система контейнера. Railway поддерживает это через Volumes — платформа, рассчитанная именно на такие маленькие сервисы. При необходимости туда же в один клик добавляется управляемый PostgreSQL (`New` → `Database` → `PostgreSQL` в том же проекте) — не нужно переезжать на другую платформу, когда появится реальная БД.

## Шаги

1. **Создайте аккаунт** на [railway.app](https://railway.app) (через GitHub — проще всего).
2. **New Project → Deploy from GitHub repo** → выберите этот репозиторий.
3. **Важно: задайте Root Directory = `server`** в настройках сервиса (Settings → Root Directory) — репозиторий содержит несколько независимых проектов (`PigeonDrop/`, `server/`), Railway должен собирать именно `server/`. Без этого сборка либо не найдёт `package.json`, либо соберёт не то.
4. Railway автоматически определит Node.js-проект и запустит `npm install && npm start` — ничего дополнительно настраивать не нужно (`package.json`'s `start` уже `node server.js`).
5. **Добавьте Volume**: Settings → Volumes → New Volume, точка монтирования — любая, например `/data`.
6. **Переменные окружения** (Settings → Variables):
   - `STORAGE_DIR=/data` — тот же путь, что точка монтирования volume на шаге 5. Без этого JSON-файлы и `uploads/` будут писаться в эфемерную файловую систему контейнера и теряться при каждом редеплое.
   - `DEFAULT_SERVER_URL=https://<ваш-домен>.up.railway.app` — публичный адрес, который выдаст Railway (виден в Settings → Networking после первого деплоя, или Generate Domain там же, если ещё не выдан).
7. После деплоя скопируйте выданный домен и обновите:
   - `PigeonDrop/config.js`: `SERVER_URL` и `WEB_APP_BASE_URL`.
   - Пересоберите приложение (`zeus build`) и сделайте `zeus preview` заново.

## Проверка после деплоя

```bash
curl https://<ваш-домен>.up.railway.app/setup
```
Должна вернуться HTML-страница (200). Затем — полный сквозной тест с реальных часов, как обычно.

## Локальная разработка не меняется

Без `STORAGE_DIR` в окружении всё работает как раньше — файлы пишутся рядом с `server.js` (`server/data/`, `server/uploads/`, `server/server.log`). `STORAGE_DIR` нужен только при деплое.
