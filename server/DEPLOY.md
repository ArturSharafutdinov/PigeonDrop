# Деплой сервера на VPS через Coolify и CI/CD

Сервер из `server/` собирается в Docker-образ и работает на вашем VPS под управлением Coolify. После пуша в `main` GitHub Actions прогоняет проверки и, если они прошли, просит Coolify выкатить новую версию. Приложение на часах так не выкладывается: оно публикуется через Zepp.

## Как это работает

```
git push в main
   └─ GitHub Actions (.github/workflows/ci.yml)
        ├─ server       — тесты сервера + сборка Docker-образа
        ├─ watch-app    — тесты приложения для часов
        ├─ watch-build  — zeus build (приложение собирается)
        └─ deploy       — только если прошёл `server` и менялась папка server/
             └─ Coolify API → Coolify забирает код через GitHub App,
                собирает server/Dockerfile и перезапускает контейнер
```

- Деплой ждёт только проверок сервера: если упали тесты часов, сервер всё равно выкатится. Сами проверки при этом покажут красный статус.
- Пуш, который не трогает `server/`, сервер не перезапускает. Ручной запуск («Run workflow») выкатывает всегда.
- Деплой **считается неудачным**, если Coolify сообщил о провале сборки: задача в GitHub станет красной.

## Настройка один раз

### 1. Coolify: создать приложение

1. **Project → New → Application → Private Repository (with GitHub App)**, репозиторий `ArturSharafutdinov/PigeonDrop`, ветка `main`.
2. **Build Pack: Dockerfile**. **Base Directory: `/server`**, Dockerfile Location: `/Dockerfile`. Без Base Directory Coolify не найдёт `Dockerfile`: репозиторий содержит несколько независимых проектов.
3. **Ports Exposes: `3000`**.
4. **Domains**: `https://<ваш-поддомен>`. У DNS-провайдера должна быть A-запись поддомена на IP вашего VPS. Сертификат выпустит Traefik сам.
5. **Environment Variables**: `DEFAULT_SERVER_URL=https://<ваш-поддомен>` (без слеша на конце). Это публичный адрес сервера; по нему часы узнают, куда отправлять записи.
6. **Persistent Storage → Add → Volume Mount**: имя `pigeondrop-data`, Destination Path `/data`. Именно **Volume**, а не Directory: контейнер работает не от root и сможет писать только в том, что Docker создал по образу. В `/data` лежат аккаунты, история загрузок, сами записи и `server.log`. Без тома всё теряется при каждом деплое.
7. **Resource Limits**: ограничьте память, например `512M`. VPS общий, а серверу этого с запасом хватает.
8. **Health check** оставьте по умолчанию: проверку задаёт сам Dockerfile (`/setup`).
9. **Advanced → Auto Deploy: выключить.** Это важно. Иначе Coolify выкатит версию сразу по пушу, не дожидаясь проверок, и вдобавок деплой запустится второй раз из GitHub Actions.

### 2. Coolify: токен для API

1. **Settings → Advanced → API Access** включить, если выключено.
2. **Keys & Tokens → API tokens** создать токен с правами `read` и `deploy` (больше не нужно). Токен показывается один раз.
3. UUID приложения: он в адресной строке на странице приложения (`.../application/<UUID>`).

### 3. GitHub: секреты

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**, три секрета:

| Имя | Значение |
|---|---|
| `COOLIFY_URL` | адрес вашего Coolify, например `https://coolify.example.com` |
| `COOLIFY_TOKEN` | токен из шага 2 |
| `COOLIFY_APP_UUID` | UUID приложения |

Токен храните только там. Без этих секретов задача `deploy` ничего не делает и пишет предупреждение: пушить в таком состоянии безопасно.

### 4. Первый деплой

После пуша в `main` откройте вкладку **Actions**. Если секреты добавили уже после пуша, запустите вручную: **Actions → CI/CD → Run workflow**. Проверка:

```bash
curl -i https://<ваш-поддомен>/setup
```
Должно вернуться `200` и HTML-страница.

### 5. Переключить часы на новый сервер

1. В `PigeonDrop/config.js` поставьте `SERVER_URL` на новый адрес (`WEB_APP_BASE_URL` берёт его сам).
2. `cd PigeonDrop && zeus preview`.
3. На часах: **Настройки → Настройка сервера**, затем **Синхронизация**. Новый сервер не знает старых аккаунтов, а часы запоминают адрес сервера после синхронизации, и он важнее `config.js`: без этого записи уйдут на старый адрес.

## Повседневная работа

- **Откат:** в Coolify на странице приложения откройте **Deployments** и выберите **Redeploy** у предыдущей версии. Либо `git revert` и пуш.
- **Логи:** в Coolify (вкладка Logs). Кроме того, сервер пишет `server.log` в `/data` без ротации; он будет расти.
- **Время:** контейнер работает в UTC, поэтому имена файлов в `uploads/` на сервере получают время по UTC (на локальном компьютере было бы местное).
- **Резервные копии:** тома `pigeondrop-data` в Backrest пока нет. Подключается тем же способом, что и другие ваши проекты.
- **Безопасность:** у сервера нет авторизации, а `GET /uploads` открыт всем, кто знает адрес. Вы решили оставить это как есть (прототип); имейте в виду, что адрес теперь публичный.

## Проверки локально

```bash
cd server && npm test        # сервер: запускает настоящий server.js на свободном порту
cd PigeonDrop && npm test    # часы: настоящий код приложения с заглушками Zepp OS
docker build -t pigeondrop-server server    # образ собирается
```

Что проверяют тесты часов (`PigeonDrop/test/`): протокол загрузки по частям и все его сбои, экран главной страницы (удержание при записи и отправке), экран настроек и то, что `config.example.js` содержит все константы, которые импортирует код.
